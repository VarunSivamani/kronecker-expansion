Session 7 · Embedding Design Study

Sum the waves, don't fill the grid: a Fourier alternative to Kronecker byte codecs

Kronecker embeddings place each byte into a fixed 256×32 grid — cheap, vocabulary-independent, and silently blind past the 32nd byte. This study replaces the grid with a sum of sinusoidal waves and measures, on a real trained model, whether that actually fixes the wall.

01The wall, made concrete

The Kronecker codec only ever looks at a token's first 32 bytes. Type a word below and watch which bytes the codec actually sees versus which ones are silently dropped.

Byte-window inspector — pos_dim = 32
Devanagari and Telugu spend 3 bytes per character in UTF-8, so the same 32-byte window that covers 32 English characters covers roughly ten. Cells past the window are dropped from the encoding entirely, with no error raised.

02Two codecs, one interface

Both codecs turn a token's raw bytes into a fixed-size vector, then pass it through one shared trainable projection. What differs is how bytes become that vector.

Kronecker — placement

Each byte is dropped into cell (value, position) of a 256×32 grid, one-hot. Position selects a slot — once 32 slots are full, later bytes have nowhere to go.

Code dim: 8,192 · fixed length: 32 bytes

Fourier — superposition

Each byte contributes a wave — frequency from its value, phase from its position — and all waves are summed. Summation never runs out of room, so length is unbounded.

Code dim: 256 · fixed length: none

04Measurement 2 — can a trained model use the difference?

A distinct vector is only useful if a model can learn to act on it. A tiny transformer (2 attention blocks, d_model=64) was trained identically on both codecs on a 4-way classification task where solving the colliding-pair half of the vocabulary requires distinguishing tokens beyond byte 32.

05Measurement 3 — is the win free?

The Fourier codec must not win simply by being a larger, more expensive codec. Both projections were sized independently of vocabulary — the property that made Kronecker attractive in the first place.

07Real-data validation — 5 languages, real Wikipedia text

Everything above uses a vocabulary engineered to force the failure mode. This section reruns the comparison on real text: a shared 16,000-token WordPiece tokenizer trained across five real Wikipedia corpora — English, Hindi, Kannada, Tamil, Telugu — chosen to span the exact fertility range the design predicts matters. Two tiny causal transformers (plus a plain dense-embedding baseline) were trained on the shared corpus and evaluated per language.

08Fertility by language, measured on real text

English spends about 1 byte per character in UTF-8; every Brahmic script here spends roughly 2.5–2.7. This is not a synthetic assumption — it's measured directly from the real corpora against the shared tokenizer.

english: 1.00 · hindi: 2.53 · kannada: 2.65 · telugu: 2.57 · tamil: 2.64 — all four Brahmic scripts cluster together, well above English, and are not interchangeable with each other despite the similar bytes/char.

09The predicted collision pattern, reproduced on real tokens

At the shipped pos_dim=32, real collisions on this vocabulary are rare — but they exist, and their rate across languages tracks fertility almost exactly, with zero collisions for English and the highest rate for Tamil.

% of real tokens colliding under pos_dim=32, by language
English: 0 / 4,051 distinct tokens used. Hindi: 0 / 5,398. Kannada: 2 / 4,146. Telugu: 10 / 4,441. Tamil: 24 / 6,066 — the highest-fertility script in this set collides most often, exactly as the mechanism predicts.

10Hyperparameter sweep — where does the wall actually close?

pos_dim=32 is a shipped default, not a derived value. Sweeping it against the real 5-language vocabulary shows exactly where the collision rate reaches zero.

Kronecker: pos_dim vs. real collision rate vs. projection params
Collision rate drops from 4.72% (pos_dim=16) to 0.13% (32, shipped) to exactly 0.00% at pos_dim=64 — double the shipped window, at double the projection cost. pos_dim=96 buys nothing further on this vocabulary.
Fourier: num_freqs (K) vs. average validation perplexity
No clean monotonic trend across K=32–256 at this (light, 2-epoch) sweep budget — reported as an open question rather than a resolved result. Unlike Kronecker's pos_dim, which has a sharp, interpretable collision-driven signal, Fourier's capacity knob does not show an obvious bottleneck being relieved in this range.

11Does the codec choice change model size?

A third baseline — a plain nn.Embedding lookup table — was trained for direct comparison, so "smaller than a dense table" has an actual reference point instead of just being smaller than the other structured codec.

Codec params as % of total trained model, vs. dense-embedding baseline
At this vocabulary (16,000 tokens, d_model=128): Kronecker's codec is 51.2% the size of what a dense table alone would cost; Fourier's is 1.6%. Session 7's own accounting shows this gap widens sharply at production vocabulary sizes (131K+), where a dense table alone exceeds a billion parameters.

12Language-modeling quality — an honest, mixed result

This is reported without smoothing it over: on real next-token prediction, Kronecker matched or beat Fourier on perplexity in 4 of 5 languages, and the dense baseline beat both structured codecs everywhere.

Validation perplexity by language and codec (lower is better)
Fewer than 0.5% of tokens in any language actually collide under Kronecker at pos_dim=32 on this vocabulary — the collision effect is real (sections 08–09) but too rare, at only 3 training epochs, to dominate perplexity over ordinary optimization noise. The synthetic experiment above isolates the effect on purpose by making colliding tokens decisive for the task; real Wikipedia text does not stress the failure mode nearly that hard.

13Where this is honest about its limits

Fourier accuracy on the synthetic colliding group is ~86%, not 100% — because bytes are summed, not placed, a long shared prefix still dominates the sum's energy and the differing suffix is a smaller perturbation on top. This is a real cost of superposition versus placement, not a free win. On real text, the collision pattern reproduces exactly as predicted and closes completely by pos_dim=64, and both structured codecs are meaningfully smaller than a dense embedding table — but real-data language-modeling perplexity does not yet show Fourier beating Kronecker: the collision effect is precisely measured yet too rare (under 0.5% of tokens per language) to dominate a short training run. Sequence-position embeddings were held fixed throughout across every experiment here — this work isolates the token codec only.
