Technical report of the solution

Problem. Paper / Session 7 Kronecker builds each token as a sparse marking on a fixed 256 × pos_dim grid (UTF-8 byte value × byte position), then applies one shared Linear(D, d_model) with D = 256·pos_dim. The default pos_dim = 32 creates two failures: (1) hard crop — bytes past column 32 never enter the code, so long Indic pieces that share a prefix collide silently; (2) wasted columns — short tokens leave most one-hot positions as exact zeros while still paying full D.

Solution (ours). Keep the Kronecker compositional event byte × position, but replace the finite one-hot position basis e_p ∈ R^{pos} with a continuous Fourier feature φ(p) ∈ R^{r} defined for every byte index. Code width stays fixed D = 256·r; length L is unrestricted (soft guardrail only). The only trainable input object remains the projection — same architectural contract as the paper module.

Paper Classic

κ = (1/√L) · vec Σ_{p < pos} c_b ⊗ e_p D = 256 · pos bytes with p ≥ pos are dropped

Ours Fourier-Position

κ = (1/√L) · vec Σ_{p = 0..L−1} c_b ⊗ φ(p) φ_{2i}=sin(p/θ^{…}), φ_{2i+1}=cos(…) D = 256 · r  (no hard crop)

Proof setup. Tokenizer xlm-roberta-base; data wikimedia/wikipedia en/hi/ta/te/kn (120k chars each); tiny causal LM d=256, L=4, heads=4; 3 epochs; CUDA. Nine curated runs (Classic pos∈{16,32,64,128}, Fourier r∈{16,32,64,128} abs, + r=32 relative). Full interactive evidence below.

Glossary — what the terms mean

Read this once; every chart and table below uses these words.

pos_dim
Paper Kronecker’s byte-position window: how many UTF-8 byte slots the grid has (columns). Default 32. Only the first pos_dim bytes of a token are kept. Example: pos_dim=32 ⇒ at most 32 bytes enter the code; byte 33+ are thrown away.
crop@32
crop@N
Fraction of token instances in the corpus whose UTF-8 surface is longer than N bytes (here N=32, the paper default). Those tokens are truncated by Classic Kronecker. Reported as a rate (0.469% = 0.00469) or percent. crop@32 = 0 on English in our run (no token needed >32 bytes). On Tamil it was 0.469% — small but real, and Indic bytes/token are still ~2.5× English.
hard crop
The irreversible truncate itself: Classic never sees bytes past pos_dim. Two different words that agree on the first 32 bytes get the same κ forever (silent collision).
fertility
Tokenizer tokens per whitespace word: (# subword tokens) / (# words). Higher ⇒ the language is split into more pieces ⇒ more attention cost for the same text. Our run: kn≈2.91, te≈2.71, ta≈2.66 vs en≈1.59 — Dravidian text is “more expensive” per word.
bytes/tok
Mean UTF-8 byte length of a token’s surface string (what Kronecker actually encodes). Indic scripts often use 3 bytes per character, so bytes/tok is much higher than English even when fertility looks moderate.
D
code dim
Width of the Kronecker code vector κ before the Linear. Classic: D = 256 × pos_dim. Fourier: D = 256 × r. pos_dim=32 or r=32 ⇒ D=8192 (paper default budget).
r / pos_features
Fourier’s position-feature width (how many sin/cos dims φ(p) has). Role analogous to Classic’s pos_dim, but does not cap token length.
matched D
A fair compare where Classic and Fourier use the same code width D (hence same projection shape Linear(D → d_model)). Only the codec differs. classic_pos32 vs fourier_r32_abs are both D=8192.
emb-path params
Trainable parameters in the input embedding path only — here the projection D × d_model (e.g. 8192×256 = 2,097,152). Does not count the transformer body or LM head.
val loss / ppl
val loss = mean cross-entropy on held-out blocks (lower better). ppl (perplexity) = exp(val loss) (lower better). Absolute values are high on this tiny proxy (huge vocab, little data) — compare deltas between arms.
Δ (C − F)
classic_val_loss − fourier_val_loss. Positive ⇒ Fourier wins (lower loss). Example: Δ=+0.122 at D=8192.
absolute vs relative
How Fourier indexes position: absolute uses byte index 0,1,2,… ; relative uses p/(L−1) ∈ [0,1] so short/long words share a unit interval. Absolute is better here for distinguishing long suffixes.
κ (kappa) / codec
The deterministic vector built from a token’s bytes (no learned weights). Classic or Fourier. Then emb = Linear(κ) produces the model input.
silent collision
Two different token strings → identical κ under Classic because they only differed after the crop window. No error is raised; the model simply cannot tell them apart.
